# Clayette Edu System (プログラミング教室 管理・学習システム)

本システムは、プログラミング教室の管理者（講師・サポーター）と、受講生（生徒・保護者）をつなぐ、ゲーミフィケーションを取り入れた統合学習プラットフォームです。

## 🛠 テクノロジースタック
*   **フロントエンド**: React, Vite, Tailwind CSS
*   **バックエンド / データベース**: Firebase (Firestore, Storage, Authentication)
*   **その他技術**: Web Audio API (効果音), CSS Animations, lucide-react (アイコン)

---

## 👥 ユーザー権限（ロール）とできること

システムには大きく分けて **管理者（講師・サポーター）** と **生徒／保護者** の2つの権限が存在します。

### 1. 👑 管理者（講師・サポーター）の機能
*   **受講生・保護者管理**: 
    *   生徒情報の登録・編集・削除（ログインID/PW自動生成機能）
    *   生徒削除時、紐づく学習記録・ファイル・チャットの**一括安全削除（カスケード削除）**
    *   ガチャ＆ゲームの挙動を手軽に確認できる「10000pt テストアカウント一発作成」機能
*   **学習記録の承認と評価**:
    *   生徒が提出した学習記録・振り返りシートの確認
    *   講師からのコメント入力（※コメントを送信すると生徒にガチャ用ポイントが1pt付与されます）
*   **教材（カリキュラム）管理**:
    *   YouTube動画や外部Webリンクを用いた教材の追加・編集・非公開設定
    *   ダウンロード用ファイルの個別リンク付与機能
*   **お知らせ（アナウンス）管理**:
    *   全員に向けたアップデートや連絡事項の掲示
*   **目標・振り返りテンプレート設定**:
    *   生徒が学習後に答える「振り返り項目（テキスト、選択式、チェックボックス等）」の動的作成
*   **チャットメッセージ機能**:
    *   各生徒・保護者との1対1のダイレクトメッセージ
*   **作品（.sb3ファイル）管理**:
    *   生徒ごとのScratchプロジェクトファイルのアップロード先確認とダウンロード

### 2. 🎒 生徒／保護者の機能（マイページ）
*   **ゲーミフィケーション（成長システム）**:
    *   これまでに取り組んだ教材数に応じて「レベル」が上がり、キャラクターが進化
*   **ガチャ＆装備システム**:
    *   学習をして貯めたポイント（1回10pt）で「装備ガチャ」を回せる
    *   C / B / A / S / SS の5段階レアリティ。引いたレアリティに応じた**専用の演出動画（フルスクリーン）**が再生される
    *   入手した装備（武器・防具・装飾品）をセットすることで、「HP・攻撃力・防御力」がアップ
    *   重複したアイテムはインベントリ（持ち物リスト）で「x2」「x3」と整理されて表示
*   **タイピングバトルゲーム**:
    *   ローマ字入力で敵を倒す、全20ステージのRPG風タイピングゲーム
    *   後半ステージ（Stage 11〜20）は非常に強力な敵が登場するため、Sレア以上の装備が必須
    *   攻撃・被弾時の**画面揺れアニメーション**や、**レトロな効果音（Web Audio API）**によるリッチな演出
*   **学習と記録（カリキュラム）**:
    *   管理者が登録した教材の一覧閲覧、ダウンロードリンクへのアクセス
    *   レッスン終了後の「目標と振り返り」の提出
*   **チャットシステム**:
    *   管理者（講師・サポーター）宛の1対1メッセージ送受信（未読・既読管理付き）

## 🔒 セキュリティとパフォーマンス最適化（Data Fetching）
本システムでは、スケール時（生徒数が増加した際）のパフォーマンス維持のため、厳密なデータ分散がおこなわれています。

*   **完全なデータの分散提供**: 
    *   データベース（Firestore）への問い合わせ時、ログインしているユーザーの権限を判定。
    *   生徒や保護者でログインした場合、**「自分に紐づくデータ（自分の記録、自分の持ち物、自分宛のメッセージ）のみ」**をサーバーから取得します。他人のデータや全リストを裏側でダウンロードしないため、万単位のユーザー登録があっても生徒側の画面表示は常に最速を保ちます。
*   **Firestore通信（バッチ処理）の最適化**:
    *   複数件のチャット未読件数処理など、データベースへの書き込み負荷を抑えるため `writeBatch` トランザクションを利用し、Firebase無料枠に優しい設計にしています。
